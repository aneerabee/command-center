🛠️ تحديث الأدوات (الأحدث ٢٠٢٦) + ركائز عرضيّة لا تُنسى

بعد تحقّقٍ بحثيٍّ من كلّ أداة — معظمها الأفضل ويبقى — هذه الترقيات الأقوى/الأحدث، وستّ ركائز تمسّ كلّ الخطوات قبل الحجز:

ترقيات مؤكَّدة:
  • ESLint ١٠ لا ٩ (٩ قارب نهاية الدعم) + typescript-eslint projectService.
  • lefthook بدل husky (أسرع، بلا إقلاع Node، ملفّ واحد) · knip ٦ + إعداد مكتوب (knip.config.ts).
  • المراقب الثاني في نطاق فشلٍ مختلف (cron خارجيّ لا Railway) + Object Lock على النسخ (مضادّ للفدية).
  • المخزون: UPDATE ذرّيّ محروس + قيد CHECK(remaining≥0) — أمتن من FOR UPDATE وحده.
  • API: HMAC على (الطريقة+المسار+بصمة‌الجسم+الوقت) لا الشكل الضعيف + @upstash/ratelimit (نافذة منزلقة لكلّ شريك) + مدقّق vacuum بدل Spectral المتوقّف.
  • المال: dinero نواة bigint · اختبارات التسعير تأكيداتٌ بالقرش لا لقطات معتمة.
ركائز عرضيّة (تُدمَج عبر الخطوات):
  • 🔭 المراقبة والتتبّع: سجلّات JSON (pino) + تتبّع موزّع (OpenTelemetry) + ميزانيّات أخطاء/SLO — قبل بناء الحجز.
  • 🧪 بيئة تجريب وكتيّبات: تجريب→إنتاج + تراجع/استرجاع/تدوير أسرار موثَّقة.
  • 🔐 تقوية أمان: تدقيق RLS لكلّ الجداول + تدوير الأسرار + فحص OWASP + ترقيم مفاتيح API.
  • 🗃️ تمرين ترحيل بيانات: لقطة إنتاج مجهّلة → تجريب، تمرين كلّ مهاجرة ٣ مرّات + نشر كناريّ.
  • 💳 قرار الدفع: تحويل/ائتمان B2B (يُسجَّل إيصالاً) أم بوّابة بطاقات (Stripe، PCI)؟ — قرارٌ قبل الحجز.
  • 📝 سجلّ تغييرات العقود: واجهة «ماذا تغيّر» + مقارنة + موافقة، فوق لقطات آلة الزمن.

⛔ لوحة العوائق

مرتّبة بالأولويّة.

عاجلفوترة GitHub متوقّفة منذ ٤ يونيو — الحُرّاس (٨ ورك‌فلو: نسخ + فحوص + تنبيهات) تموت عند بوّابة الفوترة قبل أن تبدأ. لا إصلاح كود يساعد حتى تُدفَع.
عاجل٨ قرارات مالك معلّقة قبل بناء الحجز + المحاسبة (المتتبّع أعلاه).
مهمّلا دورة حجز ولا مخزون/إتاحة ولا ماليّة بعد — أكبر فجوة بنيويّة للتحوّل إلى منصّة (مصمَّمة بالكامل، تنتظر البناء).
مهمّcontract_changes بلا RLS — مكشوف لمفتاح anon. تفعيل RLS بسياسات مناسبة.
مهمّالمكان الثاني للنسخ (Backblaze B2) — الدليل جاهز، ينتظر إنشاء الصندوق · استرجاع مختبَر · تدوير مفتاح Supabase.

١ الرؤية والهدف

ما هو الآن

نظام تسعير عقود الفنادق + بحث يعمل رسميّاً لـBRIX Travel. الموظّف يبحث (فندق/تواريخ/إشغال) فيحصل على السعر الدقيق بالقرش من العقود المُدخَلة، ثمّ يحجز يدويّاً بالبريد.

الأهداف

القريب (٧/١٠ مُنجَز): أداة داخليّة دقيقة جدّاً، صفر خطأ سعريّ، سريعة وآمنة.
البعيد (٥/١٠): منصّة B2B تتّصل بها وكالات — الفجوة بنيويّة: يتوقّف عند «هذا هو السعر».
القاعدة الذهبيّة: صفر نسبة خطأ في المال · كلّ تعديل يحترم استقلال الوحدات (الليقو) · التحقّق الحيّ قبل تأكيد أيّ إنجاز.

  • مصادقة احترافيّة (جلسات httpOnly، تجريد ترويسات التزييف).

الضعف

  • الحُرّاس (ESLint منتهٍ، لا Prettier/خطّافات، CI ناقص).
  • لا migrations في المستودع (البنية حيّة فقط).

٤ دورة الحجز والمحاسبة (المخطّط الكامل)

صُمّم بـ٨ خبراء + ٣ تدقيقات عدائيّة (٣٨ ثغرة عولِجت). تصميم فقط — لم يُبنَ، ينتظر القرارات الثمانية.

آلة حالات الحجز الموحَّدة

استعلام → عرض سعر → خيار(مؤقّت) → مؤكَّد → تسجيل دخول → مكتمل ↘ ملغًى ↘ لم يحضر
كلّ حجز: مرجع PNR · أسماء الضيوف · فاوتشر · تواريخ · ترانسفير خاصّ · لقطة سعر مجمَّدة (تكلفة+بيع+هامش). التأكيد معاملة واحدة ذرّيّة + منع تكرار.

💸 المحاسبة: دفترٌ واحد + تتبّع المال▾
دفترٌ عامٌّ مزدوجٌ واحد؛ الذمم الدائنة (ندفع للفنادق/المصادر) والمدينة (نستلم من الشركات/الأفراد) مناظير فوقه. خزينة واحدة تعرف أين المال بأيّ عملة. المال أعداد صحيحة. توازن شامل = صفر.
# عند التأكيد — أربعة أطراف متوازنة: مدين ذمم الزبون(بيع) دائن الإيراد(بيع) مدين تكلفة المبيعات دائن ذمم المورّد(تكلفة) # نستلم: مدين نقد/دائن ذمم — ندفع: مدين ذمم المورّد/دائن نقد # الهامش: مستحقّ → قابل للتحصيل → مُحقَّق (الرصيدان صفر)
كشف حساب وإغلاق لكلّ شركة (فترات مغلقة لا تُعدَّل، حارس قاعدة).
🔔 التنبيهات + المستندات + التقارير▾
التنبيهات: دخول قريب ← طالِب بالدفع (حسب جدول الدفعات) · استحقاق المورّد · ذمّة متأخّرة · تجاوز ائتمان · أسماء ناقصة. عبر تلغرام+بريد، اقتراحٌ لا فعلٌ تلقائيّ يمسّ المال.
المستندات: فاوتشر/فاتورة/كشف/إيصال عبر Gotenberg + قوالب BRIX؛ سلسلة ترقيم واحدة؛ تأكيد «إجماليّ المستند = المُقيَّد فعلاً».
التقارير: ربح/خسارة لكلّ حجز·زبون·فترة · أعمار الذمم · موقع الخزينة · «ماذا أُحصّل هذا الأسبوع».
🚧 تحقّق صادق: المكتمل والناقص▾
النواة قويّة (~٨٥٪) لكنّها ليست دورةً مكتملةً ١٠٠٪ بعد. حُلّت تعارضات (٤ جداول أطراف→واحد · ٣-٤ دفاتر→واحد · ٥ ترميزات عملة→واحد · ٣ آلات حالات→واحدة).

حرِج طبقة الإقامة/تسجيل الدخول · حرِج المخزون/الإتاحة · عالٍ محرّك سياسة الإلغاء · عالٍ جدول الدفعات/العربون.

بنية جديدة لا توجد: بريد صادر (Resend/SMTP) · مهامّ مجدوَلة بمفتاح سرّيّ · منع تكرار · RLS على جداول التكلفة/الهامش · قفل الفترات.

  • Dedup للـwebhooks · تعافٍ من partial-failure · env validation.
  • تطابق تامّ مع /search — مختبَر بـ٢٠+ سيناريو حافة + ٨ حيّة.

٦ الدستور (لا يُكسَر)

  • الليقو: حدّد القطعة المتأثّرة قبل أيّ تعديل؛ لا لمس lib/pricing/ ولا بنية الجداول لتغييرات الواجهة/البيانات.
  • التحقّق: «تأكّد» = فحص حيّ (curl على الإنتاج). الحاجز الأخضر بعد كلّ تغيير.

  • التواصل: عربيّ فصيح، بلا جداول، بلا مصطلحات (عدا أسماء الملفّات). تلغرام (chat 278516861). واجهة التطبيق إنجليزيّة LTR فاتح.
  • الأوامر: «ادفع»=push origin main. «افحص»=وكلاء متوازون. «اشرحلي»=عربيّ ثمّ موافقة.
  • الأمان: لا كشف مفتاح Supabase (يُحقَن عبر railway run)؛ المالك يدوّره.

⚙️ مطبّات محرّك التسعير▾
  • hotel_id: base_rates.hotel_id قابل للـnull → إدخال بلا hotel_id ينجح صامتاً لكنّ الأسعار غير مرئيّة. دائماً SELECT rt.hotel_id.
  • تصادم placeholder الدليل (is_directory=true): افحص وUPDATE بدل INSERT. فيض numeric(7,4): استعمل base=100. تجنّب النسب غير المنتهية.
  • PER_UNIT يطبّق المضاعف لا PER_ROOM. CROSS JOIN للرضّع. مسار submit لا يكتب young_children. الحدّ الكبير: بُثّ بدفعات ٥٠٠ — لا تترك نصف حالة.
💰 دروس المال (الأغلى)▾
  • لا تغيّر سعراً دون قراءة العقد كاملاً + تحقّق حيّ. سنغيت/غرينوود/شيروود: «إصلاحي» كان سيُحمّل الضيوف زائداً — إنذارات كاذبة. ٣٧ من ٣٨ صفّ رضيع مجّانيّ.

🔍 دروس الوكلاء والتدقيق▾
