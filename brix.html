📍 الموقف
النظام حيٌّ على Railway (الإصدار v15.5) ومرتبطٌ ببوت @BrixPrice_bot (نفس محرّك التسعير، نفس النتيجة). قفزة هذا الشهر: صار ١٣٩ فندقاً مُدخَلاً ومتحقَّقاً بالقرش (صفر تسريب مال عبر تدقيقات سلوكيّة وحسابيّة وعقود متعدّدة الوكلاء)، ٢٤٧٣ اختباراً، ٤٠ جدولاً. وأُنجِزت: الوثيقة المرجعيّة الجامعة + الفحص الشامل الصادق + إعادة تصميم لوحة المستخدمين Workbench + ستيكرز v2 + تحديث SPO ٣٤ فندقاً + مخطّط دورة الحجز والمحاسبة الكامل.

⛔ العوائق الحاليّة

عاجلفوترة GitHub متوقّفة منذ ٤ يونيو — الحُرّاس (النسخ + الفحوص + التنبيهات، ٨ ورك‌فلو) معطّلة. تموت عند بوّابة الفوترة قبل أن تبدأ.
عاجل٨ قرارات مالك معلّقة قبل بناء الحجز + المحاسبة (القسم القرارات).
مهمّلا دورة حجز ولا مخزون/إتاحة ولا ماليّة بعد — أكبر فجوة بنيويّة للتحوّل إلى منصّة (مصمَّمة، تنتظر البناء).
مهمّتصحيحات الوثيقة المرجعيّة (٨ تصحيحات دقّة) مدفوعة؛ تبقى بنود مال معلّقة (رسم رضيع +٢٥٪ بـ٣ فنادق، بريستيج ألانيا، ٤ غرف كريستال، فيلا ريكسوس).

◆ القرارات المعلّقة (تنتظر حسمك)

ثمانية قرارات تفتح بناء دورة الحجز + المحاسبة — مرتّبة بالأهمّيّة. كلّ قرارٍ يغيّر أرقاماً لاحقة.

١
متى نعترف بالإيراد والتكلفة؟
عند التأكيد (الهامش يظهر فوراً وتقدر تطالب بذمّة) أم عند الدخول/الخروج (أنظف للإلغاءات قبل الإقامة)؟ يحدّد كلّ رقمٍ لاحق.
٢
حدّ الائتمان عند التجاوز: حظر أم تحذير أم موافقة مالك؟
ذاكرتك تميل إلى «حذّر لا تمنع»؛ أكّدها للمال. وبعملةٍ واحدة أم لكلّ عملة؟
٣
سياسة الإلغاء وعدم الحضور
مبلغ ثابت، نسبة من البيع، أم سلّم لكلّ فندق من العقد (محرّك يحسبها تلقائيّاً)؟
٤
العملات والصرف
يورو فقط أم يورو/ليرة/دولار؟ ومن يزوّد الأسعار (يدويّ بالمحاسب أم سحب يوميّ)؟ وإعادة تقييم الأرصدة شهريّاً أم تحقيق الفرق عند التسوية؟
٥
الأفراد: دفعٌ مُسبق فقط أم ائتمان صغير؟
النقد-فقط (دفع قبل الفاوتشر، بلا ذمّة) يبسّط تدفّقهم كثيراً.
٦
الفاتورة: قانونيّة ضريبيّة أم بروفورما؟ + ضريبة القيمة المضافة
يحدّد صرامة الترقيم ومعالجة الضريبة التركيّة. إن لا ضريبة — نوثّقها قراراً لا إغفالاً.
٧
مزوّد البريد + مكتبة المال
Resend أم SMTP من بريدك الحاليّ؟ ومكتبة المال: dinero.js أم نوع داخليّ بسيط (أنسب لاستقلال الليقو)؟
٨
سجلّ wo_* + نافذة المطالبة
نستورد الـ٢٥٧ تحويلاً و٥٢ إغلاقاً كأرصدة افتتاحيّة أم نبدأ نظيفاً؟ وكم يوماً قبل الدخول يُطلِق تنبيه «طالِب بالدفع» (١٤؟ ٢١؟).
بنود مال أخرى معلّقة (تدقيقات سابقة، إصلاح بيانات فقط بانتظار موافقتك): رسم رضيع خاطئ +٢٥٪ بـ٣ فنادق (Asteria Bloom/Turan Prince/Club Turan، العقد «الرضيع مجّانيّ») · بريستيج ألانيا (2A+2C+رضيع=2.0 بدل 2.5) · ٤ غرف كريستال (max_infants=2) · فيلا ريكسوس كلوب بريفيه (قصّ ٣٣٧٤٫٩٩). وبنود قديمة: سجلّ تغييرات العقود · فجوة «بالغان+طفل» (~٥٠ غرفة) · حظر رضيع تحت‑٧ (لاقون) · ليماك (دفع SQL) · فجوة تغطية Land of Legends نوفمبر · ٧٩ غرفة max_infants=0.

١ ما هو BRIX — الرؤية والهدف

ما هو الآن

نظام تسعير عقود الفنادق + بحث يعمل رسميّاً لـBRIX Travel. الموظّف يبحث (فندق/تواريخ/إشغال) فيحصل على السعر الدقيق بالقرش من العقود المُدخَلة، ثمّ يحجز يدويّاً بالبريد.

الأهداف

القريب (مُنجَز ٧/١٠): أداة داخليّة دقيقة جدّاً، صفر خطأ سعريّ، سريعة وآمنة.
البعيد (٥/١٠): منصّة B2B احترافيّة تتّصل بها وكالات/شركاء — الفجوة بنيويّة: النظام يتوقّف عند «هذا هو السعر».
القاعدة الذهبيّة: صفر نسبة خطأ في المال · كلّ تعديل يحترم استقلال الوحدات (الليقو) · التحقّق الحيّ قبل تأكيد أيّ إنجاز.

٢ ما في السيستم الآن (الحالة التقنيّة)

٢.١ المعماريّة والأدوات

Next.js 16TypeScript صارمSupabase PostgresRailwayVitestPlaywrightTailwind 4
  • القاعدة: ٤٠ جدولاً (مصدر الحقيقة الوحيد).
  • النشر: Railway تلقائيّ من main (~٩٠ث)؛ /api/version يُرجِع git.commitSha.
  • الاختبار: ٢٤٧٣ ناجحاً + ٥ متخطّاة (١١٢ ملفّاً) + Playwright + عتبة تغطية ٨٠٪.
  • التدفّق: Supabase ← Next.js API ← الواجهة. الإدخال يكتب لـSupabase؛ البحث يقرأ ثمّ يمرّ بالمحرّك.

٢.٢ مبدأ الليقو (القانون الأوّل)

كلّ وحدة في lib/ قطعة مستقلّة. حساب التسعير نقيّ ومعزول (calculatePrice/night-calculator لا يلمسان الواجهة/القاعدة). دقّة: الوحدة تضمّ أيضاً data-loader.ts (يقرأ Supabase) ويُصدَّر لمسار البحث عبر unified-pricing-engine.ts — فالنقاء يخصّ الحساب لا كامل سطح الوحدة. الهامش والربح والرؤية فوق المحرّك لا داخله.

٢.٣ الأقسام

  • البحث والتسعير: /search ← /api/search ← المحرّك (per-period + شارات).
  • معالج العقود: /contract-wizard (٨ خطوات) + تعديل: /contract-edit/[hotelId].
  • لوحة المستخدمين (مالك): أدوار · صلاحيّات رؤية · رؤية الهامش · ماركأب لكلّ مستخدم · تجاوزات لكلّ فندق · تعديل بالجملة · ستيكرات المدير.
  • لوحات admin: time-machine · audit-logs · contract-log · eb-alerts · occupancy-gaps.
  • مصادر الأسعار /sources · ملفّات العقود/SPO (Gotenberg) · النسخ + time-machine.

٢.٤ نموذج التسعير

night = round(base_night_price × occupancy_multiplier, 2) total = Σ كلّ ليلة بسعر فترتها
  • المعامل = الحقيقة الكاملة (بالغين+أطفال+رضّع برقم واحد).
  • حِيَل: PER_PERSON×ÇARPAN أو base=10/100 (base=100 إذا المعامل ≥١٠٠٠ لسقف numeric(7,4)).
  • فئتا طفل: child_split_age+young_children (الرضيع [0,infant_age_max) مجّانيّ غالباً).
  • ٨ أنواع خصم: EB · LONG_STAY · SPECIAL · SENIOR · HONEYMOON · PROMO · EARLY_PAYMENT · DISCOUNT_PP. دمج EXCLUSIVE→الأفضل، CAN_COMBINE→تراكميّ.
  • الماركأب بعد المحرّك (PER_NIGHT). إيقاف البيع: تحذير برتقاليّ «راجع السيد هيثم» (لا يمنع).

صُمّم بـ٨ خبراء + ٣ تدقيقات عدائيّة (٣٨ ثغرة عولِجت). تصميم فقط — لم يُبنَ. ينتظر قرارات القسم «القرارات».

آلة حالات الحجز الموحَّدة

استعلام → عرض سعر → خيار(مؤقّت) → مؤكَّد → تسجيل دخول → مكتمل ↘ ملغًى ↘ لم يحضر
«مُعدَّل/فاوتشر‌صادر/مُسوّى» = أحداث/مشتقّات لا حالات. كلّ حجز: مرجع PNR · أسماء الضيوف · فاوتشر · تواريخ · ترانسفير خاصّ · لقطة سعر مجمَّدة (تكلفة+بيع+هامش). التأكيد معاملة واحدة ذرّيّة + منع تكرار UNIQUE(booking_id,'confirm').

💸 المحاسبة: دفترٌ واحد + تتبّع المال▾
دفترٌ عامٌّ مزدوجٌ واحد؛ الذمم الدائنة (ندفع للفنادق/المصادر) والمدينة (نستلم من الشركات/الأفراد) مناظير فوقه. خزينة واحدة تعرف أين المال بأيّ عملة. المال أعداد صحيحة. توازن شامل = صفر (فحص ليليّ).
# عند التأكيد — أربعة أطراف متوازنة: مدين ذمم الزبون (بيع) دائن الإيراد (بيع) مدين تكلفة المبيعات دائن ذمم المورّد (تكلفة) # نستلم: مدين نقد / دائن ذمم الزبون — ندفع: مدين ذمم المورّد / دائن نقد # الهامش = بيع − تكلفة، متتبَّع. حالاته: مستحقّ → قابل للتحصيل → مُحقَّق(الرصيدان صفر)
كشف حساب وإغلاق لكلّ شركة (فترات مغلقة لا تُعدَّل، حارس قاعدة).
🔔 التنبيهات + المستندات + التقارير▾
التنبيهات: دخول قريب ← طالِب بالدفع (حسب جدول الدفعات) · استحقاق المورّد · ذمّة متأخّرة · تجاوز ائتمان · أسماء ناقصة · عدم حضور. عبر تلغرام+بريد، اقتراحٌ لا فعلٌ تلقائيّ يمسّ المال.
المستندات: فاوتشر/فاتورة/كشف/إيصال عبر Gotenberg + قوالب BRIX؛ سلسلة ترقيم واحدة؛ تأكيد «إجماليّ المستند = المُقيَّد فعلاً».
التقارير: ربح/خسارة لكلّ حجز·زبون·فترة · أعمار الذمم · موقع الخزينة · «ماذا أُحصّل هذا الأسبوع».
🚧 تحقّق صادق: المكتمل والناقص▾
النواة قويّة (~٨٥٪) لكنّها ليست دورةً مكتملةً ١٠٠٪ بعد. حُلّت تعارضات التصاميم (٤ جداول أطراف→واحد · ٣-٤ دفاتر→واحد · ٥ ترميزات عملة→واحد · ٣ آلات حالات→واحدة).

حرِج طبقة الإقامة/تسجيل الدخول · حرِج المخزون/الإتاحة · عالٍ محرّك سياسة الإلغاء (يحسب الغرامة من العقد) · عالٍ جدول الدفعات/العربون (يُشغّل تنبيه «طالِب بالدفع»).

بنية جديدة لا توجد اليوم: بريد صادر (Resend/SMTP) · مهامّ مجدوَلة بمفتاح سرّيّ · منع تكرار · RLS على كلّ جداول التكلفة/الهامش · قفل الفترات.

٧ بوت التسعير @BrixPrice_bot

بوت الوكلاء — ست خطوات بالأزرار، ثنائي اللغة، نفس نتيجة الويب بالضبط.

التدفّق والوصول

  • المدينة ← الفندق ← تاريخ الدخول (تقويم تفاعليّ) ← الخروج ← الضيوف والأعمار ← النتيجة (أفضل الأسعار + ميداليات).
  • الوصول: دعوة بالهاتف — المستخدم يرسل رقمه، المدير يوافق، النظام يربط.
  • توقيت إسطنبول لكلّ حسابات booking-window (يحلّ مشكلة ٣ ساعات قبل منتصف UTC).

المتانة والأمان

  • إغلاق HTML injection · حماية من انتحال جهات الاتصال · إصلاح race conditions · منع تسرّب PII · rate limit · تحقّق UUID.
  • Dedup للـwebhooks · تعافٍ من partial-failure · معالجة stale callbacks · env validation.
  • تطابق تامّ مع /search — مختبَر بـ٢٠+ سيناريو حافة + ٨ حيّة على الإنتاج.

٨ الدستور (القواعد الثابتة — لا تُكسَر)

  • الليقو: حدّد القطعة المتأثّرة قبل أيّ تعديل؛ لا لمس lib/pricing/ ولا بنية الجداول لتغييرات الواجهة/البيانات.
  • التحقّق: «تأكّد» = فحص حيّ فعليّ (curl على الإنتاج)، لا tsc+vitest فقط. الحاجز الأخضر بعد كلّ تغيير.
  • المال: لا تغيّر سعراً دون قراءة العقد كاملاً + تحقّق حيّ بالقرش. لا تثق بإنذار وكلاء قراءة الملفّات — تحقّق يدويّاً.
  • التواصل: عربيّ فصيح، بلا جداول، بلا مصطلحات إنجليزيّة (عدا أسماء الملفّات). تقارير HTML حيّة. التواصل اليوميّ تلغرام (chat 278516861).
  • واجهة التطبيق: إنجليزيّة بسيطة (LTR فاتح).
  • الأوامر: «ادفع» = git add+commit+push origin main (conventional + Co-Authored-By). «افحص» = وكلاء متوازون. «اشرحلي» = عربيّ ثمّ موافقة.
  • الأمان: لا كشف مفتاح Supabase (يُحقَن عبر railway run)؛ المالك يدوّره ويضيف أسرار GitHub بنفسه.

٩ الدروس والقوانين والمطبّات

كلّ واحدة كلّفت خطأً أو وقتاً — احترمها في كلّ تعديل مستقبليّ.

⚙️ مطبّات محرّك التسعير▾
  • hotel_id على base_rates و occupancy_multipliers: base_rates.hotel_id قابل للـnull → إدخال بلا hotel_id ينجح صامتاً لكنّ الأسعار غير مرئيّة. occupancy_multipliers.hotel_id NOT NULL (يفشل بصوت). دائماً SELECT rt.hotel_id.
  • تصادم placeholder الدليل: is_directory=true → INSERT بنفس الاسم يُرجِع صفّين. افحص وUPDATE بدل INSERT.
  • فيض numeric(7,4): سقف المعامل 999.9999. مع base=10 فيلا ≥١٠٠٠٠ يفشل → استعمل base=100.
  • تجنّب النسب غير المنتهية (7/3، 16/7 تحمل قصّ ≤€٠٫٠٤)؛ base=10 يتجاوزها.
  • PER_UNIT يطبّق المضاعف، PER_ROOM لا. CROSS JOIN للرضّع يقلّل الصفوف ×٣.
  • فئتا الطفل: مسار submit للمعالج لا يكتب young_children (انتبه). الحدّ الكبير للتنفيذ: بُثّ REST بدفعات ٥٠٠ — لا تترك نصف حالة.
  • النموذج الموحّد base=10/100: الكرت يكشف baseIsPlaceholder ويُظهر سعر الشخص الحقيقيّ.
💰 دروس المال (الأغلى)▾
  • لا تغيّر سعراً دون قراءة العقد كاملاً + تحقّق حيّ. درس سنغيت/غرينوود/شيروود: «إصلاحي» كان سيُحمّل الضيوف زائداً — كلّها إنذارات كاذبة. ٣٧ من ٣٨ صفّ رضيع تُسعَّر مجّانيّةً.
  • الرضيع مجّانيّ غالباً [0, infant_age_max) — لا تفرض معامل الطفل المدفوع (كان خطأ +٢٥٪ بـ٣ فنادق).
  • خصم هيثم (سوينو): «Our contract» ٤٥٪/٥٠٪ دائم — لا يُحذف أبداً.
  • عروض SPO = ملفّات عرض فقط (لا أرقام في المحرّك) ما لم يقرّر المالك؛ الاستثناء = سوينو فقط.
🔍 دروس الوكلاء والتدقيق▾
  • لا تثق بإنذار وكلاء قراءة الملفّات — تحقّق يدويّاً. أخطؤوا في كريستال/ريكسوس/SPO/الرويال/Palmora.
  • التحقّق العدائيّ إلزاميّ: «٤ عقول/ملاحظة» قلّص ١١٣ ملاحظة واجهة إلى ٣ حرِجة فعليّة.
  • اختبر مخرَج المحرّك الحيّ لا العقود الساكنة (السلوكيّ: ١٣٩٠ بحثاً + قواعد ثبات).
🎨 مطبّات الواجهة▾
  • Portal للنوافذ الثابتة إلى document.body. سلّم z: dropdown 50 / sticky 100 / fixed 200 / modal 5000-5001 / popover 10001 / tooltip 10002 / banner 1000.
  • minmax(0,1fr) لمسارات الشبكة + min-width:0. النمط الأبرز للعلل: قصّ overflow أو سياق تكديس + z خارج السلّم.
  • احترم prefers-reduced-motion + لمسات هاتف ٤٤px + aria. التطبيق إنجليزيّ LTR فاتح (لا RTL داكن).
🛠️ قوانين تشغيليّة▾

  • snake_case في route.ts. /api/version يُرجِع git.commitSha تحت مفتاح git لا الجذر؛ حاجب /api/admin/* يعطي 401 حتى لمسار غير موجود.
